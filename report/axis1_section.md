## Method

**Research question (RQ1).** How much of the coverage of an LLM-generated heuristic depends
on meaningful names in the PDDL input?

Corrêa et al. [1] observed that the heuristic generated by DeepSeek-R1 for Blocksworld solves
66 tasks, but only 40 after renaming every symbol to a random string, while $h^{\mathrm{FF}}$
is unaffected (27 vs. 28 tasks). That experiment uses one domain, one model and a single
level of obfuscation. We turn it into a benchmark: all eight IPC 2023 Learning Track domains,
four graded levels, and several independent renamings per level.

**Obfuscation levels.** We implemented a PDDL obfuscator that parses each domain and task
and renames symbols through one consistent mapping per domain. The mapping is applied to the
domain file, to every training and test task, and to the example state and static facts
included in the prompt. All comments are removed, since several IPC files describe the
domain in comments (e.g. Sokoban tasks include an ASCII drawing of the level).

- **L0 (original).** The unmodified files. We regenerate L0 with the same model and protocol
  as the other levels instead of reusing the archived heuristics of [1], because the model
  behind the provider's endpoint has changed since then.
- **L1 (renamed schema).** Domain name, types, constants, predicates, actions and variables
  are replaced by random 8-character strings. Object names in the tasks are kept.
- **L2 (renamed and shuffled).** L1, plus random object names, plus a random permutation of
  predicate declarations, actions, action parameters, precondition and effect conjuncts,
  task objects, initial facts and goal conjuncts. No lexical cue is left. This is the
  setting closest to the Obfuscated Blocksworld of [1] and the "Mystery" domains of
  Valmeekam et al. [3, 4].
- **L3 (misleading).** Every symbol, objects included, is renamed with meaningful words from
  a different domain of the benchmark (Blocksworld ↔ Transport, Childsnack ↔ Rovers,
  Miconic ↔ Sokoban, Floortile ↔ Spanner). The structure is untouched, so L3 against L1/L2
  separates the effect of *missing* cues from the effect of *wrong* cues.

**Several renamings per level.** A single random renaming could be accidentally easy or hard.
Following the professor's suggestion, we generate independent copies of the same level
with different random seeds and report the spread across copies.

**Sanity check.** $h^{\mathrm{FF}}$ ignores names, so its coverage must not change across
levels. We run Pyperplan with $h^{\mathrm{FF}}$ on the training tasks of every level; any
change in coverage would reveal a bug in the obfuscator.

**Protocol.** We follow the shared protocol of the project (Section 4): for each domain and
level, the LLM ([model, TBD]) generates $n = 10$ candidate heuristics with the prompt of [1],
using the obfuscated domain, two obfuscated example tasks and an obfuscated example state.
Each candidate guides GBFS in Pyperplan on the 20 training tasks (60 s); the candidate with
the highest training coverage (ties broken by expansion and agile score, as in [1]) is
evaluated on the 30 test tasks (300 s, 4 GiB). We report coverage, the outcome of every
candidate (crash, infinite heuristic, timeout, solved) and node expansions.

## Results

**Sanity check.** $h^{\mathrm{FF}}$ solves all 20 training tasks of every domain at L0, L1,
L2 and L3, so the obfuscated tasks are equivalent to the originals. The number of expanded
nodes is identical to L0 on 25–100% of the tasks, depending on the domain. The differences
come from tie-breaking in the open list, which depends on symbol names and on the order of
actions and facts. Comparisons of expansions across levels should therefore be read with
this noise in mind.

## Limitations

- One model family and $n = 10$ candidates (the paper used $n = 25$); time limits are shorter
  than in [1] (5 min instead of 30 min).
- The training set of the shared protocol contains the 20 smallest tasks, so several
  candidates may solve all of them and selection is decided by tie-breaking.
- L1 keeps object names, which can still reveal the domain (e.g. `rover1`, `waypoint3`).
  This is intended (it isolates schema names) but L1 is therefore not fully anonymous.
- Obfuscation cannot rule out that the model recognises a domain from its structure alone.
